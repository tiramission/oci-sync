UI Designer · 设计规范

oci-sync 界面设计方案

TUI 与 GUI 共用一套信息架构与视觉语言：仓库 → 产物 → 动作 → 详情。补齐推送入口、统一动作作用域、让破坏性操作有明确的确认边界。

oci-sync 0.7.0 WCAG AA 对比度达标 双端同构 键盘优先

01设计基础

TUI 只能用 8/16 色的 ANSI 调色板，GUI 有完整 RGB 主题。两者不能共用一套颜色定义，但必须共用语义——同一个状态在任何一端都是同一个颜色角色。

02信息架构

现有 TUI 只有 pull / delete，GUI 才有 push——同一个工具两套心智模型，用户在终端里发现「推不上去」。方案把三个动作并列成一个动作区，并明确各自的作用域。

层级承载设计要点
① 仓库层左栏 shortcut 列表名称为主、repo 路径为辅；行尾角标显示已加载的 artifact 数，避免切换后数一下。窄屏折叠为单栏时，顶部保留面包屑可返回。
② 产物层主栏表格四列固定语义：标签 / 大小 / 加密 / 版本。加密列是唯一值得在扫视中被一眼捕捉的信息，用警示色 + 加粗，其余保持安静。
③ 动作区表格下方推送作用域是仓库（未选中行也可用）；拉取 / 删除作用域是行。作用域不同必须在视觉上区分，否则会出现「为什么这里推不了」。
④ 详情弹窗 / 抽屉展示 digest、标签、上传时间；并支持就地增删标签——原来只能读标签却不能改，是最明显的能力缺口。

05状态设计

空、错、忙三态是这个工具最高频的界面状态——因为它绝大部分时间在等网络往返。

状态文案原则示例与处理
空说清原因 + 给出下一步「此仓库还没有 artifact」→ 紧跟一个主行动按钮「推送…」。不写「暂无数据」这种死胡同文案。
空（被过滤）与真空态区分开「没有 tag 匹配 “v3”」+ 清除过滤的链接。不能和「仓库为空」共用一句话。
加载不让布局跳动表格区显示 6 行骨架行而非 spinner 居中，避免刷新时高度塌陷再撑开。
错误给原因 + 给出路「认证失败：凭据已过期 → 重新登录」；网络超时给重试按钮并保留当前选中行。
进行中可见可取消阶段名 + 字节计数 + 已用时，Esc 随时可撤。取消后回到原上下文，不重置选择。

06交互原则

破坏性操作

  • 删除必须二次确认，且默认焦点在「否」
  • 确认框显示完整 repo:tag，不用缩写
  • 文案写明不可撤销的后果，不写「确定吗？」
  • 危险按钮与其他按钮保持 ≥8px 间距，防误触

信息呈现

  • 大小用人类可读单位，digest 走等宽字体
  • 加密状态用文字 + 颜色双通道，不靠颜色单独表意
  • 时间用相对时间（3 小时前），绝对时间放详情
  • 路径过长中间省略，保留首尾可辨认部分

键盘与可达性

  • TUI 全流程可纯键盘完成，无鼠标依赖
  • 焦点环始终可见，对比度 ≥3:1
  • GUI 弹窗打开时焦点锁定在弹窗内
  • Tab 顺序：工具栏 → 仓库 → 表格 → 动作

响应式

  • TUI <76 列折叠单栏，保留面包屑
  • GUI <860px 左栏收为下拉选择器
  • 最小 720×420 下弹窗字段全部在视口内
  • 表格列按可用宽度依次隐藏「版本 → 加密」
